# Changelog

All notable changes to Wee Spurts. Newest at the top. Updated on request.

## [Unreleased]

### Design
- **Throw mechanic locked** (`GameBible.md` §8; feel-knobs stay open in `OpenQuestions.md`). Miss-timing on the power meter = *grounded human-fumble chaos*: bad timing distorts direction/spin so the thrower visibly screws up (never supernatural or world-breaking), good timing stays clean and predictable (the competitive hook). Escalation is **non-linear** — small misses mild, big whiffs spectacular — with named failure archetypes (Hook / Chip / Overcook / Whiff) hand-placed at the meter extremes. Skill = consistency and style, not scoreboard domination (pin scatter + betting/heckle/drink layers keep it level). Refined from an earlier Sonnet draft of the same idea.

### Added
- **Nuke Shot powerup (sandbox/prototype)** — GameBible §9's first powerup: cartoon-logic spectacle, sanctioned exception to §8's grounded-realism rule. New `IsNuke` flag + tunables on `BallConfig` (`NukeBlastRadius`, `NukeExplosionForce`, `NukeTweenDuration`, `NukeLockOnPauseDuration`, `NukeGreenZoneMin`/`Max` — the Nuke's own green window, currently `0.82`–`0.85`; **explicitly left unchanged from the earlier `0.80`–`0.83` polish-pass item at Tony's request**). Green release (read from the SAME `TimingError01`/green-zone signal every throw already computes, via a new `BallLauncher.SetGreenZone(min,max)` override — no second timing signal): ball hides, a canned-tween sphere (`NukeShotResolver`, new) flies up, camera follows it up slowly (`ThrowCamera.FollowRising`), hard-cuts to a behind/above shot for a "locking on" pause (`ThrowCamera.CutToBehindAbove`), rockets down onto the pins, and `PinDeck.ApplyExplosion`/`Pin.ApplyExplosion` (`Rigidbody.AddExplosionForce`, `ForceMode.Impulse`) sends them flying for pure visual spectacle. **The scored outcome is a guaranteed full clear** (`knocked = Scorer.PinsStanding`, read directly, zero dependency on whether the physics impulse actually toppled every pin) — a deliberate design guarantee, not a physics-derived result, so it's trivially host-authoritative once networked. Miss (non-green): detonates in-hand at chest height, ends the whole turn as a punishing whiff — including forcing the frame to actually complete first (an extra `AddRoll(0)` if needed) so the shared `PinDeck` never desyncs from the next player's turn. Registered in the sandbox `BallConfigSwitcher`. TODO-commented hooks left in `NukeShotResolver` for future sound/VFX (not built yet). `NukeSphere`'s default collider removed (cosmetic tween only, never a physical obstacle); `NukePoof` particle system fixed to a one-shot burst with a URP-compatible shader (was looping forever and rendering magenta — Unity's default missing-shader fallback, not intentional). Defensive `ResetVisualState` cleanup runs at the top of every roll so an interrupted sequence (e.g. the sandbox `F`-key reset firing mid-tween) can't leave a stuck sphere, looping poof, or invisible ball behind.
- **Bowling feel prototype: timing chaos, Body English, Wobbler ball** (sandbox/prototype — none of this is a locked Bible decision; feel-knobs below stay open in `OpenQuestions.md`).
  - **`LaunchParameters` gained `TimingError01`** (-1 late .. 0 perfect .. +1 early) and **`IsBackwardFumble`** (bool), both computed by `BallLauncher` at release from the power meter.
  - **Power meter reworked**: the old repeating ping-pong triangle wave is gone. Holding SPACE now rises the meter once from 0→100% and caps there (no more falling back down mid-hold). A tunable **green zone** (80–85% default) on `BallLauncher` counts as a perfect release; `DebugHud`'s power bar now draws that zone as a visible band. Releasing under a tiny threshold (<5% power, an accidental tap) sets `IsBackwardFumble` — a hand-placed Wii Sports-style gag where the ball flies backward instead of forward.
  - **Hook + Cone**: `BowlingBall` now applies a continuous sideways "Hook" force and a one-time seeded angle/spin "Cone" jitter, both driven by `|TimingError01|` through a new non-linear `TimingErrorCurve` (`AnimationCurve`) on `BallConfig` — mild near-zero misses, escalating sharply toward the extremes, per Bible §8. Direction/side follows `TimingError01`'s sign (early vs. late hook opposite ways). Fully deterministic: only reads `LaunchParameters` + `BallConfig`, uses `System.Random(Seed)` (never `UnityEngine.Random`) for the one-time jitter.
  - **Body English** (cosmetic): new `IThrowReactionActor` interface + greybox `CapsuleThrowReactionActor` — a capsule stand-in for the thrower leans (matching the Hook direction) or faceplants (on a backward fumble) right after release, purely visual, never touches `LaunchParameters`. Wired into `BowlingGameController` via the standard Unity `[SerializeField] MonoBehaviour` + interface-cast pattern, so a future rigged Quaternius character can implement the same interface without any wiring code changing. `GreyboxSceneBuilder` builds a translucent `ThrowerProxy` capsule for it (no collider — it's cosmetic only, never a physical obstacle).
  - **`Wobbler` ball config**: a new `BallConfig` variant with a continuous seeded sinusoidal side-force (phase from `Seed`, magnitude/frequency new `BallConfig` fields defaulting to `0` — a no-op on every other ball) — "weaves like a flat spot" per the original brainstorm. Auto-created and registered into the sandbox `BallConfigSwitcher` by `GreyboxSceneBuilder` if missing, without stomping hand-tuning on a rebuild.
- **Sandbox aim-phase preview** — while aiming, the ball now visibly slides left/right with `CurrentLateral` (previously frozen and invisible until throw), and a short curved `LineRenderer` shows intended direction (`CurrentAngle`) with a spin-biased curve preview. New `AimPreview.cs`, wired onto the ball's GameObject by `GreyboxSceneBuilder`. Both the ball position and the line reuse `BowlingGameController.HalfLaneWidth` (new public property, factored out of `ResolveThrow` so preview and resolved throw can never drift apart) — purely visual, never touches `LaunchParameters` or the resolved throw. `DebugHud` now always shows Lateral/Angle/Power/Spin as numbers while aiming (previously only Power/Spin, and only while charging). Sandbox-only, safe to remove before shipping.
- **Sandbox frame reset** — press `F` in Play mode to re-rack and replay the CURRENT frame (same player, same frame number) without ending the match. Added `BowlingScorer.ResetCurrentFrame()` (discards only the current frame's recorded rolls; earlier frames and `IsGameOver` untouched; no-op once the match is over) and a matching `BowlingGameController.ResetCurrentFrame()` that stops any in-flight throw coroutine and calls `BeginRoll()`. `DebugHud` hint updated. For repeated feel-testing of one throw setup without playing back through pin counting each time. Sandbox-only, safe to remove before shipping.
- **Sandbox ball switcher** (`BallConfigSwitcher`) — press `1`–`9` in Play mode to pick which `BallConfig` the next throw uses, for A/B feel testing and powerup prototyping. Added `SetBallConfig()` / `ActiveBallConfig` to `BowlingGameController` (config is read per-throw, so swaps apply on the next roll). `DebugHud` shows the active ball; `GreyboxSceneBuilder` auto-adds the switcher and seeds slot 1 with the default ball. Sandbox-only, safe to remove before shipping.
- **New `PinConfig` ScriptableObject** (`WeeSpurts/Pin Config` menu), same pattern as `BallConfig`/`LaneConfig`. Holds `PinSpacing`, `PinHeight`, `PinMass`, `KnockedAngleDegrees` (moved out of `LaneConfig`), plus new `Bounciness` and `Friction` tunables. `GreyboxSceneBuilder` now builds a `PinBounce` physics material from these, mirroring the ball's `BallBounce` material, so pin scatter feel is Inspector-tunable without touching code.
- **`BouncyBall` and `Cannonball` `BallConfig` assets** — example ball-feel variants for the sandbox switcher (high-bounce vs. heavy/low-bounce), for A/B testing powerup feel.

### Fixed
- **Nuke miss on a fresh frame desynced the scorer from the shared pin deck.** Ending the turn unconditionally after a whiff (without checking whether the frame's roll bookkeeping had actually finished) left the scorer expecting a second roll that never came — the next time that player was up, they'd inherit whatever pins the *other* player's last roll had left standing instead of a correctly re-racked frame. Fixed by walking the frame to actual completion (calling the existing `BowlingScorer.AddRoll` an extra time if needed, never touching its internals) before ending the turn. Provably bounded — traced every reachable state, worst case is one extra call.
- **Hook (and the matching Body English lean) hooked the wrong direction.** `Docs/OpenQuestions.md`/`Docs/BowlingFeelIdeas.md` spec "too HARD → hooks RIGHT, too SOFT → hooks LEFT"; the built code had it backwards since the mechanic was first added. Fixed the sign in both `BowlingBall.cs` and `CapsuleThrowReactionActor.cs` together (they read the same `TimingError01` sign independently — flipping only one would've made the thrower's lean and the ball's curve point opposite ways).
- **Green zone not updating on a mid-aim ball switch.** Switching to the Nuke ball *during* an already-started aim phase kept using the previous ball's (wider) green zone until the next roll — the zone only got pushed to `BallLauncher` at the start of a roll, not when the active config changed mid-aim. Fixed by re-applying the correct zone from `SetBallConfig` too, not just `BeginRoll`.
- **Wobbler force was ~30x too weak to be visible.** A sinusoidal force's peak velocity contribution is bounded by `F / (2π·frequency·mass)` — unlike a constant force (e.g. Hook), it doesn't keep accumulating over the roll. The original tuning (`3N` at `2.5Hz`) worked out to ~0.03 m/s of drift, imperceptible. Retuned to `12N` at `0.5Hz` (~0.64 m/s, and slow enough to read as one lazy weave instead of a fast shimmy).
- **Ball bounce material now uses `bounceCombine = Maximum`** (`GreyboxSceneBuilder`) so a ball's own `BallConfig.Bounciness` always wins over the lane floor's instead of averaging with it. Fixes bouncy-ball feel testing (ball was "slamming down" even at high `Bounciness`) and means future ball-feel powerup variants never need a matching floor material.
- **Switching `BallConfig` mid-session now actually changes bounciness.** `BowlingBall.Launch()` previously left the ball's physic-material bounciness at whatever the *default* `BallConfig` had baked in at scene-build time — swapping to `BouncyBall` via the sandbox switcher changed mass/speed/spin but not bounce. `Launch()` now restamps an instanced copy of the collider's physic material (`collider.material`, not `sharedMaterial`) with the active config's `Bounciness` on every throw. Also: `GreyboxSceneBuilder` now auto-seeds the switcher with `BouncyBall`/`Cannonball` if those assets exist, so they're selectable without manually dragging them into the Inspector.

### Changed
- **`LaneConfig` is lane-geometry-only now** (`Length`, `Width`, `DebugPlayerCount`) — pin physics moved to the new `PinConfig`. `PinDeck.Initialize` now takes a `PinConfig` instead of a `LaneConfig`.
- **Bowling ball now starts at chest height.** Added a `SpawnHeight` tunable to `BallConfig` (default `1.3` m) and pointed `GreyboxSceneBuilder`'s BallSpawn at it, so the ball drops onto the lane when thrown. Height is now editable in the Inspector without code.
- **Aim camera reframed** for the higher ball: raised to Y `2.3`, pulled back to Z `-3.7`, pitched down to `16°` (`GreyboxSceneBuilder` aim view).
